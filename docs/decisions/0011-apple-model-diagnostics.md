# Diagnose Apple model-service failure

Plan: isolate error 1008 with a minimal plain-text request, then structured generation and the actual summary pipeline, using synthetic content only. Run the same probe through the native test harness and an isolated normal app launch. Inspect public Apple documentation and safe domain/code diagnostics; do not infer that `.available` guarantees inference, or that an undocumented numeric error proves a specific cause. Do not accept machine-wide licenses, change system security, grant personal-source permissions or access live journals.

Implement only fixes supported by evidence, retain bounded error diagnostics and provide actionable failure text. Preserve the source-preview fallback. Evaluate changes with native checks, production build and signed packaging; document any unresolved OS/model-service gate separately from passed synthetic orchestration tests.

Results (2026-11-13): the same machine reports model availability in both execution contexts. An opt-in minimal-request test in the restricted Swift harness reproduces FoundationModels -1 / ModelManagerServices 1008 before structured generation is attempted. A normally launched, ad-hoc signed native review bundle completes minimal generation. This isolates the observed 1008 failure to the restricted harness execution context; it does not establish the meaning of Apple's internal error code or prove that no device can encounter it.

The native probe exposed a separate functional failure: generated source indices omitted the required reported account, so the existing validator correctly rejected the output. Changed prompt evidence to explicitly include zero-based `evidenceIndex` fields instead of relying on implicit array positions. Kept validation intact. The next native probe passed structured generation. Further reader-facing instructions keep technical labels/indices out of prose. A mixed-input probe then passed the actual `SummaryPipeline` with synthetic text, speech, visual clues, calendar and city weather. It retained the concert cancellation, denied attendance, ignored an injected BANANA instruction and made no Denver location claim. Source references and size/copy bounds passed. The observed output still contains an unnecessary “morning report” phrase; one fixture does not establish broad summarization quality or adversarial robustness.

Added domain/code-only error diagnostics so Foundation Models failures no longer disappear behind a generic message. Framework error descriptions/prompts/journal text are not exposed. Standard orchestration checks remain independently useful.
