# Compact, grounded summaries

Plan: replace copied daily accounts and single-entry weekly excerpts with an Apple on-device synthesis pipeline. Assemble every included saved text, available recording transcript and uploaded-media visual analysis from native storage; add connected calendar plans, photo counts and selected-city weather. Preserve provenance: calendar attendance is unknown, visual clues are uncertain, city weather does not locate the user, and unanalyzed originals contain no available event facts. Excluded memories must never enter prompts or fallback copy.

Implementation: bounded evidence batches, intermediate condensation for large inputs, structured title/detail/source references, compact final output and explicit unavailable/failure states. Process all batches or publish no generated result. Native jobs support polling/cancellation and reject source changes before publishing. React discards stale results and preserves manual overrides. A brief, labeled extractive fallback remains usable without Apple Intelligence; it must not masquerade as model synthesis.

Evaluation: synthetic tests for multimodal evidence, source exclusion, context provenance, complete batching, output bounds, cancellation/stale publication and provider failure; production build, native service tests and signed packaging. Record actual on-device model availability separately from mocked pipeline tests. Never request personal library or microphone permissions for evaluation.

Implemented: native `GroundedSummaries.swift` reads authoritative included originals, uses structured Foundation Models output, batches every source segment, condenses all batches and then the week, and validates output size/references and long verbatim copies. Jobs have polling, cancellation, a three-minute deadline and source-change checks both before publication and when reading completed results. The UI drops results whose displayed inputs changed, preserves manual headings, and provides refresh/cancel controls. The source-preview fallback is bounded and deduplicated; it is explicitly not represented as model synthesis. The daily exclusion leak is fixed.

Connected photo previews now receive cached, local Vision/OCR analysis (at most 12 displayed previews per day). Uploaded photo/video analysis and recording transcripts are used when available. Calendar context includes title, time and location, with unknown attendance. Selected-city weather includes conditions, Fahrenheit range and precipitation; failed weather requests provide no invented weather. Calendar's previous first-40 cap was removed. Sources outside the loaded photo subset, missing/cloud-unavailable previews, unprocessed audio/video, limits exceeded and model failures cannot be represented as fully understood events. Missing media analysis and the photo subset limit are disclosed.

Evaluation (November 13): 20 native and 12 web tests passed; production build, signed Mac packaging and iOS asset preparation passed. Native tests include injected-provider multimodal/exclusion/provenance, complete Unicode batching, source lineage, copy/reference/length rejection, day/week publication, stale-source rejection, cancellation and provider failure. These test orchestration and bounds, not real language quality. A separate synthetic attempt found Apple model availability `.available` but actual inference failed with FoundationModels/ModelManagerServices error 1008. Real generative quality therefore remains unverified in this environment; its failure log is preserved, not counted as a successful inference. No personal-source permissions were requested. Full Xcode/iPhone and live photo/speech inference remain device validation gates. Evidence: `reports/summaries-results.json` and `reports/summaries-*.log`.
